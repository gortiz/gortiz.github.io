Why call native code?

  • Ecosystem access — reuse Rust/C/C++ libraries that already exist.
    ML inference (ONNX), compression (zstd), databases. Don't rewrite them.
  • Ergonomics — some problems are more natural with direct memory control.
    SIMD intrinsics, memory-mapped structures, zero-copy I/O.
  • Performance — bypass JIT/GC limits…
    Be careful — the JVM is surprisingly good. Native isn't a magic speed button.

static final MethodHandle IS_MATCH = Linker
          .libraryLookup(...)
          .downcallHandle(...);

public boolean isMatch(String pat, String hay) {
    try (Arena arena = Arena.ofConfined()) {
        MemorySegment cP = arena.allocateFrom(
            JAVA_BYTE, 
            pat.getBytes(UTF_8);
        MemorySegment cH = arena.allocateFrom(
            JAVA_BYTE, 
            hay.getBytes(UTF_8));
        return (boolean) IS_MATCH.invoke(
            cP, pat.length(), cH, hay.length());
    }
}

Compiled Regex

pub struct RegexHandle { regex: Regex }

// create → Java gets a raw ptr it owns
#[no_mangle]
pub extern "C" fn create(
    pat: *const u8, len: usize,
) -> *mut RegexHandle {
    let re = Regex::new(
        bytes_to_str(pat, len)).unwrap();
    Box::into_raw(Box::new(
        RegexHandle { regex: re }))
}

// is_match → reuse the compiled regex
#[no_mangle]
pub extern "C" fn is_match(
    h: *mut RegexHandle,
    hay: *const u8, len: usize,
) -> bool {
    let h = unsafe { &*h };
    h.regex.is_match(
        bytes_to_str(hay, len))
}

// destroy → reclaim & drop the Box
#[no_mangle]
pub extern "C" fn destroy(
    h: *mut RegexHandle,
) {
    unsafe { drop(Box::from_raw(h)); }
}
class PanamaRsRegex
    implements AutoCloseable {
  final MemorySegment handle;
  final Arena arena =
      Arena.ofConfined();

  // create
  public PanamaRsRegex(String pattern) {
    var cPat = arena.allocateFrom(
        JAVA_BYTE, utf8(pattern));
    handle = (MemorySegment)
        CREATE.invoke(cPat);
  }

  // is_match — scratch arena per call
  boolean isMatch(String hay) {
    try (Arena local = Arena.ofConfined()) {
      var cHay = local.allocateFrom(
          JAVA_BYTE, utf8(hay));
      return (boolean) IS_MATCH.invoke(
          handle, cHay, cHay.byteSize());
    }
  }

  // destroy
  public void close() {
    DESTROY.invoke(handle);
    arena.close();
  }
}

Callbacks

// plain Java method — the callback target
boolean onMatch(int start, int end) { … }

// one-time: lift it into a MethodHandle
static final MethodHandle BRIDGE =
    MethodHandles.lookup().findVirtual(
        PanamaRsRegex.class, "onMatch",
        MethodType.methodType(
            boolean.class, int.class, int.class));

// one-time: downcall (last param = fn pointer)
static final MethodHandle FOR_EACH_MATCH =
  LINKER.downcallHandle(
    LIB.find("for_each_match").orElseThrow(),
    FunctionDescriptor.ofVoid(
        ADDRESS, ADDRESS, JAVA_LONG, ADDRESS));
public void forEachMatch(String haystack) {
  try (Arena arena = Arena.ofConfined()) {
    // wrap the MethodHandle as a REAL
    // native function pointer
    MemorySegment stub = LINKER.upcallStub(
        BRIDGE,
        FunctionDescriptor.of(
            JAVA_BOOLEAN, JAVA_INT, JAVA_INT),
        arena);
    MemorySegment cHay = arena.allocateFrom(
        JAVA_BYTE, haystack.getBytes(UTF_8));
    FOR_EACH_MATCH.invoke(
        handle, cHay, cHay.byteSize(), stub);
  }
}

What we built today

Five shapes that compose into any native API

  • ✓ Primitives — add(a, b)
  • ✓ Strings — isMatch(pattern, haystack)
  • ✓ Opaque native handle — a compiled Regex
  • ✓ Struct return — find() → {found, start, end}
  • ✓ Callback / upcall — streaming findAll

Master these five — the rest of any native API is just composition.

Performance tips

  • Each call is expensive.
    • JNI slower than Panama
  • One broad > many narrow.
  • Shared memory > copies.
  • Do not use Java Strings.
  • Use async-profiler — not JFR.

Toolbox

  • Build — rust-maven-plugin bundles native libs inside the jar.
  • Debugging — Two debuggers, two windows.
  • Logging — Rust log / tracing don't feed SLF4J.
  • IDEs & AI — No cross-boundary refactoring. AI shines for translation.
  • Two heaps, one process — GC knows nothing about Rust allocations.
